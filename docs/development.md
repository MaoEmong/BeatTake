# 실행 및 확인

## 작업 환경

앱 표시 이름은 BeatTake다. Flutter 코드에서 쓰는 이름은 `everyday_beats`다. Flutter 3.44.7과 Dart 3.12.2로 작업했고, Android와 iOS 프로젝트가 생성돼 있다. Android의 최소 지원 버전은 API 24다.

프로젝트 폴더에서 아래 명령을 실행한다. `flutter run`에는 연결된 휴대폰이나 가상 기기가 필요하다.

```powershell
flutter pub get
flutter analyze
flutter test
flutter run
flutter build apk --debug
flutter build apk --release
```

이 Windows PC에서는 `C:\flutter`의 설치 파일 일부가 빠져 있었다. 마지막으로 통과한 빌드는 `E:\portfolio\ieum\.build-tools\flutter\bin\flutter.bat`을 사용했다. Android SDK를 같은 위치에 둔 상태라면 다음처럼 실행할 수 있다.

```powershell
Set-Location 'E:\portfolio\vibeforge'
$env:ANDROID_HOME = Join-Path $env:LOCALAPPDATA 'VibeForgeDev\android-sdk'
$env:ANDROID_SDK_ROOT = $env:ANDROID_HOME
$vibeFlutter = 'E:\portfolio\ieum\.build-tools\flutter\bin\flutter.bat'
& $vibeFlutter doctor
& $vibeFlutter build apk --debug
```

- 안드로이드 설치 파일은 `build/app/outputs/flutter-apk/app-release.apk`에 있다. 현재 프로젝트의 기본 테스트 서명으로 만든 설치용 파일이다. 개발 중 화면과 오류를 확인할 때는 같은 폴더의 `app-debug.apk`를 사용한다.
- Android 빌드에는 SDK 35와 36, NDK 28.2.13676358, CMake 3.22.1을 사용했다.
- 코드와 패키지가 각각 E 드라이브와 C 드라이브에 있어 발생했던 Android 빌드 오류를 피하도록 `android/gradle.properties`에 `kotlin.incremental=false`를 설정했다.
- iOS는 마이크 사용 권한 문구가 들어가 있다. 빌드와 기기 확인에는 macOS의 Xcode 환경이 필요하다.

| [lib/ai_arranger.dart](../lib/ai_arranger.dart) | Gemini에 배치안을 요청하고 앱에서 쓸 수 있는 결과인지 검사한다. |
| [lib/track_editor_page.dart](../lib/track_editor_page.dart) | 곡의 전체 배치와 선택한 트랙을 보여 주고, 소리의 트랙과 시작 시간을 바꾼다. |
| [lib/settings_page.dart](../lib/settings_page.dart), [lib/copy.dart](../lib/copy.dart) | 설정, 언어별 앱 문구, Gemini 키 등록을 담당한다. |
| [test/recording_store_test.dart](../test/recording_store_test.dart) | 새로 저장소를 열었을 때 파일을 다시 찾는지, 빈 녹음이 목록에 올라오지 않는지 확인한다. |
| [pubspec.yaml](../pubspec.yaml) | 녹음은 `record`, 재생은 `audioplayers`, 앱 저장 위치 확인은 `path_provider`를 사용한다. |

녹음 파일은 앱의 문서 저장공간 안에 있는 `recordings/` 폴더에 저장한다. 녹음 중에는 `draft_<시작시각>.wav`에 소리가 쌓인다. 정지가 끝나고 파일 저장이 완료되면 `recording_<시작시각>.wav`로 이름을 바꾼다. 앱은 최종 이름을 가진 파일만 읽어 최신순으로 표시한다. 현재 형식은 모노 WAV, 44.1 kHz다.

앱이 뒤로 전환되면 진행 중인 녹음을 마치고 저장하도록 구현했다. 저장이 완료된 파일은 재시작 후에도 남는다. 녹음 중에 운영체제가 앱을 즉시 종료하면 임시 파일이 남을 수 있다. 녹음 권한을 확인할 때는 Android의 `android/app/src/main/AndroidManifest.xml`과 iOS의 `ios/Runner/Info.plist`를 확인한다.

다듬은 소리는 `recordings/clips/`에 별도 WAV 파일로 저장한다. 음을 높이면 소리가 짧아지고, 낮추면 길어진다. 편집해서 저장하거나 곡으로 재생할 수 있는 길이는 최대 5분이다. 곡의 이름과 각 소리의 트랙 및 시작 시간은 `recordings/songs/`에 저장한다. 저장된 곡에 들어 있는 소리를 삭제하려면 해당 곡에서 배치를 먼저 지운다.

AI 편곡에는 개인 Gemini 키가 필요하다. 키는 기기의 보안 저장소에 보관하고, 편곡을 요청할 때 선택한 소리의 이름과 길이, 사용자가 입력한 요청만 Gemini에 보낸다. 배치안을 받아도 곡 파일에는 **곡 저장**을 눌렀을 때 반영된다.

## 트랙 렌즈 1차 MVP

- 홈과 보관함에서는 왼쪽 메뉴를 사용한다. 녹음, 소리 다듬기, 곡 편집은 작업 공간을 넓게 쓰도록 화면 전체를 사용한다.
- 곡 편집 화면에서는 위쪽에 모든 트랙의 배치를 표시하고, 아래쪽에서는 선택한 트랙의 소리와 파형을 크게 보여 준다. 소리를 놓기 전에 곡이 5분 안에 들어오는지 확인한다.
- 영어가 기본이고 한국어, 일본어, 중국어 간체를 선택할 수 있다. 언어와 녹음 후 다듬기 화면 자동 열기 설정은 앱을 다시 열어도 유지된다.
- 원본 녹음, 다듬은 소리, 저장한 곡은 기존 저장 형식을 그대로 읽는다. AI 제작 화면에서 받은 배치안은 직접 제작과 같은 편집 화면으로 열린다.

### 1차 MVP 설치본 확인

- `flutter analyze`와 자동 검사 9개가 통과했고, 안드로이드 설치 파일을 만들어 Android 15 가상 휴대폰에서 열었다.
- 녹음 후 자동으로 다듬기 화면을 열고, 설정을 끄면 원본 보관함으로 이동하는 것을 확인했다. 녹음 중 휴대폰 홈으로 나갔다 약 0.15초 뒤 돌아오는 상황에서도 녹음이 저장됐다.
- 녹음 두 개를 다듬어 따로 저장하고 두 트랙에 배치했다. 곡을 저장하고 앱을 다시 열었을 때 두 번째 트랙의 시작 위치 0.50초가 유지됐고, 곡 보관함에서 재생할 수 있었다. 소리 끝이 5분을 넘기는 배치는 저장 전에 차단됐다.
- 곡 이름을 입력하는 키보드가 화면에 떠 있어도 재생과 소리 추가 버튼이 키보드 위에 표시된다. 소리 추가를 연달아 열고 곡을 저장할 수 있었다.
- 자동 검사에서 화면 언어 네 가지를 확인했다. 가상 휴대폰에서 한국어로 바꾸고 앱을 다시 실행했을 때 한국어가 유지됐으며, 영어로 되돌릴 수 있었다.
- 가상 휴대폰에서 Gemini 키 등록 전 안내와 인터넷이 끊겼을 때의 안내를 확인했다. 자동 검사에서 시험용 응답을 처리했다. 실제 Gemini 키를 사용한 편곡과 실제 휴대폰의 마이크, iOS 빌드 및 재생은 확인 전이다.
- 앱 표시 이름을 BeatTake로 바꾼 뒤 안드로이드 설치 파일과 홈 화면의 새 이름을 확인했다. 사용 중이던 가상 휴대폰에 업데이트해 기존 원본, 다듬은 소리, 저장한 곡을 보관함에서 다시 열 수 있었다. iOS는 표시 이름과 마이크 권한 안내 설정을 확인했다.

### 브라우저에서 소리 확인

브라우저 미리보기는 가상 휴대폰 화면을 보여 준다. 녹음은 이 PC의 마이크로 하고, 재생은 윈도우 기본 소리 출력 장치를 사용한다.

미리 듣기가 안 들린다는 보고를 확인했을 때 저장된 약 4.5초의 원본과 다듬은 파일 모두에 소리 신호가 있었다. 가상 휴대폰의 미디어 볼륨을 5에서 13으로 올린 뒤, 원본 재생과 다듬기 화면의 미리 듣기 모두에서 윈도우 기본 출력 장치로 신호가 전달되는 것을 확인했다.

## 작업 단계별 확인 결과

- **녹음**은 Android 15 가상 휴대폰에서 마이크 권한 허용, 녹음 정지 후 저장, 앱 재시작 후 목록에서 다시 열기를 확인했다.
- **소리 편집**은 구간을 줄이고 음을 높여 미리 듣고, 다른 이름으로 저장한 뒤 원본과 다듬은 소리가 함께 남는 것을 확인했다. 한 옥타브를 높이거나 낮출 때의 소리 데이터와 길이도 자동 검사로 확인했다.
- **트랙과 곡 관리**는 서로 다른 두 트랙을 합친 재생 파일을 만들고, 배치를 수정해 저장한 뒤 앱 재시작 후에도 바뀐 트랙 위치를 표시하는 것을 확인했다. 사용하는 곡이 있는 동안에는 소리 삭제를 막고, 곡을 삭제한 뒤에는 소리가 지워지는 것도 확인했다.
- **AI 편곡**은 시험용 응답으로 사용자가 고른 소리만 배치하며, 목록에 없는 소리를 돌려받으면 결과를 거부하는지 확인했다. 가상 휴대폰에서는 설치본을 업데이트해도 시험용 키가 유지되고, 편곡에 쓸 소리를 고르는 화면이 열리는 것을 확인했다. 실제 Gemini 키로 응답을 받는 검사는 남아 있다.
- **공통 검사**로 `flutter analyze`와 자동 검사 7개가 통과했다. 안드로이드 설치 파일의 서명을 확인하고, 가상 휴대폰에 설치해 앱을 실행했다. 실제 휴대폰의 마이크와 iOS 빌드 및 재생은 확인 전이다.

## 2026년 11월 24일 설치본 재검사

Android 15 가상 휴대폰의 새 환경에 `app-release.apk`를 설치해 화면에서 직접 조작했다. 자동 검사 7개도 다시 통과했다.

- 마이크 권한을 거부하면 설정 안내가 표시됐다. 다시 녹음을 눌러 권한을 허용한 뒤 녹음, 정지, 저장이 됐다.
- 원본 녹음을 자르고 음 높이를 바꿔 미리 듣고 저장했다. 다듬은 소리가 목록에 추가됐고 원본도 남았다.
- 두 트랙에 소리를 배치해 재생하고 곡을 저장했다. 앱을 다시 열었을 때 두 번째 트랙의 시작 위치 0.25초가 유지됐다. 시작 시간으로 300초를 입력하면 범위를 안내했다.
- 곡에서 쓰는 소리는 삭제할 수 없다는 안내가 나왔다. 곡을 지운 뒤에는 해당 소리를 삭제할 수 있었다.
- 시험용 Gemini 키를 넣고 인터넷을 끈 상태에서 편곡을 요청했다. 연결 오류를 안내했고 기존 곡의 소리 배치는 유지됐다. 정상 응답 처리는 시험용 응답을 사용한 자동 검사로 확인했다.

**확인된 문제**는 녹음 중 홈 버튼을 누르고 곧바로 돌아오면 녹음이 자동으로 저장되지 않고 계속되는 경우가 있다는 점이다. 약 1초 뒤에 돌아온 첫 시도와 약 0.15초 뒤에 돌아온 시도에서 발생했다. 1초 뒤에 돌아온 다른 시도와 홈 화면에서 6초를 기다린 시도에서는 정상적으로 저장됐다.
